# سند مرجع سامانه مدیریت وصول شهرداری

## 1. مشخصات

- نام: سامانه مدیریت وصول، هزینه و صورت‌وضعیت کارگزاری شهرداری
- Backend: FastAPI + SQLAlchemy 2
- Database: PostgreSQL
- Server: Ubuntu
- Domain: `https://shahrdari-ai.com`
- مسیر استقرار فعلی Backend: `/backend-v1`
- نسخه جاری این بسته: `0.3.0`

## 2. هدف

ایجاد یک منبع داده مرکزی برای وصول، هزینه، دستمزد، صورت‌وضعیت، پرداخت، گزارش مدیریتی و ردپای حسابرسی. فایل Excel فقط کانال ورود داده است و مبنای گزارش نهایی، پایگاه داده مرکزی خواهد بود.

## 3. واحدهای عملیاتی

- منطقه ۱
- منطقه ۲
- ناحیه ۲
- ناحیه ۳
- منطقه ۳

در نسخه‌های بعدی نام جدول `regions` به‌صورت Migration کنترل‌شده به `operational_units` منتقل می‌شود؛ تا آن زمان برای جلوگیری از شکستن سورس موجود، نام فعلی حفظ شده است.

## 4. نقش‌ها

- `brokerage_head`: دسترسی کامل
- `executive_manager`: داشبورد، وصول، گزارش، صورت‌وضعیت و مشاهده Audit
- `finance_manager`: داشبورد، هزینه، پرداخت، گزارش و مشاهده صورت‌وضعیت
- `expert`: فقط بارگذاری فایل وصول واحد خودش و مشاهده نتیجه اعتبارسنجی
- `tri_manager`: فقط مشاهده داشبورد و گزارش

کارشناس هیچ داشبورد، گزارش، صورت‌وضعیت، هزینه یا پرداختی نمی‌بیند.

## 5. قواعد اصلی

- تقویم عملیاتی: شنبه تا چهارشنبه وزن ۱، پنجشنبه ۰٫۲۵، جمعه و تعطیل وزن صفر.
- قواعد دستمزد باید از فایل مرجع تأییدشده خوانده شوند و نباید در کد ثابت باشند.
- تقویم و فایل‌های مرجع قبل از تأیید مدیر قابل استفاده در محاسبات نیستند.
- هزینه‌ها شامل مستقیم و مشترک هستند. هزینه مشترک بر اساس سهم وصول واحدها سرشکن می‌شود.
- چند پرداخت برای یک صورت‌وضعیت مجاز است.
- وضعیت نهایی صورت‌وضعیت «تسویه کامل» است.
- هیچ داده مفقودی در داشبورد با عدد ساختگی جایگزین نمی‌شود.

## 6. گردش کار صورت‌وضعیت

ایجاد → سرپرست → سرپرست مالی → شهردار منطقه → مدیر درآمدهای عمومی → کمیته راهبردی → مالی → پرداخت‌های چندگانه → تسویه کامل

## 7. معماری

`Excel → Validation → Central Database → Dashboard / Statements / Reports / Payments`

لایه‌ها:

- Core: احراز هویت، مجوز، حسابرسی، قواعد مشترک
- Modules: وصول، هزینه، مرجع، صورت‌وضعیت، پرداخت، گزارش
- Presentation: API و رابط وب

## 8. تصمیم‌های نسخه 0.2.0

- Permission Engine مرکزی اضافه شد.
- مجوزها با نام قابلیت تعریف شده‌اند، نه شرط‌های پراکنده نقش.
- Audit Log عمومی برای عملیات مالی اضافه شد.
- API مشاهده Audit با فیلتر و صفحه‌بندی اضافه شد.


## 9. تصمیم‌های نسخه 0.3.0

- کارشناس پس از ورود مستقیماً وارد پنل Upload می‌شود و داشبورد ندارد.
- فایل وصول ابتدا اعتبارسنجی و Preview می‌شود و سپس با تأیید صریح ثبت نهایی می‌گردد.
- فایل تکراری با SHA-256 و ردیف تکراری با هش محتوایی مسدود می‌شود.
- ثبت رکوردها تراکنشی است و پس از موفقیت، جدول تجمیعی وصول ماهانه داشبورد به‌روزرسانی می‌شود.
